## 1. 结论

**做空已经作为一个真正的参数实现在提交文件里，经过机器精度级的数学验证、
逐位不变的回归证明、以及 4 个惩罚系数 × 8 个做空额度的完整扫描；
但出厂设置是关闭的。**

原因不是"保守"，而是四组测量数字：

1. **满仓的前提下，"可做空"与"`leverage=1`"在数学上互斥。**
   净敞口被满仓钉在 1，于是 `Gross = 1 + 2 × 总做空量`。只要开一点空头，Gross 就超过 1。
2. **在出厂惩罚系数下，做空额度基本不 binding，收益与回撤的变动都在可忽略量级**，
   而 Gross 被抬到 1.156。在排名百分位模拟里，`p=4.0` 内部换做空比例对总分的
   影响 **≤ +0.0037**（ftse100 与 factors 上恰好为 0），而同一模拟里
   **干净与崩掉之间的总分差约 0.51**——用数量级更大的风险去博千分之几的分，不划算。
3. **回撤的大幅改善（sp500 上 57% → 31%）并不是靠做空单独拿到的，而是必须同时把
   `anchor_penalty` 压到 0 附近**——而出厂 `p=4.0` 下开做空对回撤的影响不到 0.5pp
   （见 §4.1）。**而 `p` 被压低正是上一轮已经因"复现被禁的 SCM-GMVP"排除的方向**
   （5 资产面板上相关性 0.999）。所以做空没有提供一条独立于"降低惩罚"的通路。
4. **模拟里确实存在比出厂设置高 +0.018 ~ +0.070 的设置，但它们都要 Gross 1.3 – 2.3、
   而且最优设置在不同数据集上不一致**（见 §4.4）。**出厂设置不是模拟得分的最高者，
   它是"在 `leverage=1` 的四种解读下都合法"的那一个。** 这是主动取舍，不是遗漏；
   若评测框架确认只约束净敞口，§8 给出了改成那条路的一步操作。

「做空比例」这个旋钮我手调了 8 档、在 4 个惩罚系数下各扫一遍、跑满 3 个数据集，
全部结果在下文表格与 `reports/round2_short_sweep.{json,txt}`。
**老师的规则允许做空，但并不要求做空**；
`allow_short=False` 在 `leverage=1` 的**每一种**解读下都合法。

## 2. 为什么这是一个真冲突，而不是理解问题

skfolio 库里**没有** `leverage` 参数（库内只有财务杠杆类**因子**），
所以 `leverage` 是评测框架自己的规则。它唯一可测量的对应物是
`MultiPeriodPortfolio.long_short_exposure` 的四个量：
`Long` = 正权重和、`Short` = 负权重和、`Net` = 权重和、`Gross` = 绝对权重和。

满仓（`sum(w) = 1`）时恒有

```
Net   = Long − Short = 1
Gross = Long + Short = 1 + 2 × Short
```

于是"`leverage=1`"的四种自然读法与做空的关系是：

| 读法 | 约束 | 做空空间 |
|---|---|---|
| ① Gross 上限 + 强制满仓 | `Gross ≤ 1` 且 `Net = 1` | **无**（数学上只剩 `w ≥ 0`） |
| ② 真杠杆率 | `Gross / Net = 1` | **无** |
| ③ Gross 上限，不强制满仓 | `Gross ≤ 1` | 有，但净敞口 `= 1 − 2×Short` 被压低 |
| ④ 只约束净敞口 | `\|Net\| ≤ 1` | 有，且可保持满仓 |

**long-only 满仓在 ①②③④ 下全部合法。**
而本次实现的 `{w ≥ −c, sum(w) = 1}` 是"满仓 + 每资产可做空"，
它只在 ④ 下合法；在 ① ② ③ 下 Gross 都会越界。

这是一个**不对称赌注**：开启做空只会增加"被判违规"的面数，而失败率占 70% 的分。
所以默认值是关闭，并且这个取舍写在 `configs/submission_round2.json` 的
`short_selling_note` 里，不是藏在代码里。

## 3. 实现了什么

### 3.1 参数

```python
def allocate(returns, *, half_life=63.0, recent_mix=0.25, anchor_penalty=4.0,
             method="regularized", allow_short=False, short_cap=0.0):
```

- `allow_short=False` → 可行集仍是 long-only 单纯形 `{w ≥ 0, sum(w) = 1}`。
- `allow_short=True, short_cap=c` → 可行集换成盒子单纯形 `{w ≥ −c, sum(w) = 1}`。
- `short_cap > 0` 但 `allow_short=False` 会**抛错**，而不是被静默忽略。
- `short_cap` 被限制在 `[0, 0.5]`。

### 3.2 数学：两处闭式都改了，并且都验证过

换成盒子单纯形以后，`project_simplex` 和"单纯形对偶间隙"都不能直接用，
否则求解器的收敛证书会**失效但看不出来**。两处都换成闭式解：

```python
# 投影：平移后就是标准单纯形，用排序阈值法，闭式
u = w + c                          # 双射到 {u ≥ 0, sum(u) = 1 + n·c}
budget = 1.0 + n * c
# ... 排序阈值投影 ...
w = max(z − θ, 0) − c

# 对偶间隙下界：凸集上线性型在顶点取到最小值，仍然闭式
min_g = min(gradient)
lower = (1.0 + n·c) · min_g − c · Σgradient     # c = 0 时退化为 min_g
```

**验证方式不是"权重合法就算过"**，见 `tools/round2_short_projection_check.py`：

| 断言 | 独立参照 | 实测最大误差 |
|---|---|---|
| 投影 = 精确欧氏投影 | 对 KKT 乘子二分求解 | **1.4e-15**（机器精度） |
| 投影 = 精确欧氏投影 | cvxpy 直接解投影问题 | 1.6e-11（求解器容差） |
| 间隙下界 = 线性型最小值 | cvxpy 解 LP | 4.3e-12（求解器容差） |
| 下界确实是下界 | 逐可行点逐个检验 | 无违例 |

### 3.3 证明"加了参数没动老路径"

新增参数最容易出的事故是**顺手改了老代码路径**。这里用冻结的改造前核心做黄金参照
（`research/round2/frozen/core_r2_long_only_80bbd559.py`，SHA256 `80bbd559...`），
对新旧两版跑同一批面板 × 同一组参数，**要求 `np.array_equal` 而不是 `allclose`**：

```
tools/round2_long_only_equivalence.py
  cases compared   : 220
  differences      : 0
  intended fixes   : 10
  LONG-ONLY EQUIVALENCE: IDENTICAL
```

**220 个 case 逐位一致。** 其中 10 个 case 被单独归类为"有意修复"（见 §7），
门会强制要求它们**只以那一种方式**不同：必须走上已认证的 QP 路径、不得留下内部异常、
权重必须合法；`method="hrp"` 的那一例权重还必须逐位不变（只有状态标签被纠正）。

**出厂惩罚系数 `anchor_penalty = 4.0`：**

|---|---|---|---|---|---|---|

| 0.01 | 16.393% | 56.564% | 0.057 | 1.115 | 0.750 | 0.5163 |
| 0.02 | 16.383% | 56.568% | 0.076 | 1.153 | 0.755 | 0.5090 |

同样在出厂 `anchor_penalty = 4.0` 下：

|---|---|---|---|---|---|
| **0.00（出厂）** | **13.684%** | 45.668% | 0.000 | **1.000** | 1.048 |

方向上与 sp500 一致（年化下降、回撤改善），但**量级大得多**：年化 **−0.86pp**、
回撤 **−1.92pp**，Gross 从 1.000 抬到 **1.371**。

### 4.2b factors（5 资产，100 折，0 失败）

| `short_cap` | 年化 | 最大回撤 | 实际总做空 | Gross | 与 SCM-GMVP 的 L1 |
|---|---|---|---|---|---|
| **0.00 – 0.50（全部）** | 10.925% | 39.874% | **0.000** | **1.000** | 1.105 |
| `p=0.00, cap=0.00`（对照，已被排除） | 10.347% | 38.863% | 0.000 | 1.000 | **0.030** |
| `p=0.00, cap=0.20`（对照，已被排除） | 9.657% | 39.094% | 0.600 | 2.200 | 0.800 |

两点：

1. **在出厂 `p=4.0` 下，5 资产面板上做空完全不激活**——8 个额度给出逐位相同的组合。
   锚正则项在低维、低资产数时压过方差项，做空约束根本不 binding。
2. **`p=0` 的对照行把"为什么不能用 p=0"钉死了**：`p=0, cap=0.00` 与

   开做空后这个距离变大（0.030 → 0.800），但**变大的方向不是"更安全"，
   而只是"离 long-only 的那一个更远"**，见 §5 的度量边界说明。

### 4.3 排名百分位模拟：70% 那一项根本不区分

在模拟对手场（12 个 skfolio 优化器）里，所有 **0 失败**的候选——**三个数据集上都是 42 个**，
包括我们的每一个设置和 10 个对手方法——`r_fail` 是**同一个常数 0.523256**（并列共享秩）。
只有 HRP/HERC 拿到 0.012：

| 候选 | 失败率 | `r_fail` | 总分 |
|---|---|---|---|
| 全部 0 失败候选（42 个，我们 + 10 个对手方法） | 0.0% | **0.523256** | 0.477 – 0.663 |
| HRP / HERC | 99.0 – 99.8% | 0.012 | 0.008 |

也就是说，占 70% 的分项在 0 失败的群体内部**完全不区分**；真正的分差只来自另外 30%，
上限 0.30。我们全部设置的总分带：

| 数据集 | 我们 32 个设置的得分区间 | 宽度 |
|---|---|---|
| sp500 | 0.4760 – 0.5821 | 0.106 |
| ftse100 | 0.4870 – 0.6626 | 0.176 |
| factors | 0.4779 – 0.5510 | 0.073 |

**干净与崩掉之间的总分差约 0.51。** 注意这个模拟里**没有**失败率落在 1%–99% 之间的候选，
所以它**不能**给出"第一折失败值多少分"的边际标价；它能支持的是一个量级判断：
**弄坏东西的代价比调参数大一个数量级。**

### 4.4 出厂设置不是模拟得分最高的设置——这一点必须明说

| 数据集 | 出厂 `p=4.00 cap=0.00` | `p=4.0` 内最优 | `p ≥ 0.25` 内最优 | 全场第一（含 `p=0`） |
|---|---|---|---|---|
| sp500 | 0.5126 | `cap=0.01` **+0.0037** | `p=1 cap=0.05` **+0.0183** | `p=0 cap=0.50` 0.5821 |
| ftse100 | 0.5309 | `cap=0.00` **+0.0000** | `p=0.25 cap=0.20` **+0.0695** | `p=0 cap=0.01` 0.6626 |
| factors | 0.4870 | `cap=0.00` **+0.0000** | `p=1 cap=0.05` **+0.0640** | SchurComplementary 0.5785 |

三条结论：

1. **在出厂 `p=4.0` 内部，做空对得分的影响 ≤ +0.0037，在 ftse100 与 factors 上恰好为 0。**
   §1 第 2 条成立。
2. **确实存在 +0.018 ~ +0.070 的更高分设置**，但它们的共同点是把惩罚压到
   `p=1` 或 `p=0.25`、并把 Gross 抬到 **1.3 – 2.3**（超出 `leverage=1` 的 30% – 130%），
   而且**最优设置在不同数据集上不一致**（sp500 与 factors 是 `p=1`，ftse100 是 `p=0.25`；
   全场第一分别是 `p=0 cap=0.50`、`p=0 cap=0.01`、以及对手方法 SchurComplementary）。
   这是典型的**用噪声挑参数**的特征，不是稳定优势。
3. **因此出厂设置不是模拟得分的最高者，而是"在 `leverage=1` 的四种解读下都合法"的那一个。**
   这是主动的取舍，不是遗漏。如果评测框架确认只约束净敞口（读法 ④），
   那么 §8 那三行改法就是把它换成 `p=0.25–1.0` + 做空的一步操作——
   **但那一刻起 `Gross ≤ 1` 就不再成立，需要由测验方确认这是允许的。**

### 4.5 更正与稳健性：上表的对手池被我们自己的重复项污染了

⚠️ **§4.4 的"全场第一"与那些 Δ 值,是在一个被污染的池子里算出来的,必须更正。**

扫描时每个数据集的池子是 **44 项 = 12 个对手 + 我们自己 32 个设置**
（4 惩罚 × 8 做空额度,其中很多因为额度不 binding 而给出**逐位相同**的组合）。
排名百分位是对**池内相对位置**算的,32 个自己的近似重复项会互相占据名次位、
压缩彼此的百分位——**我们实际上是在和自己比,而不是和对手比**。
按 44 项算出来的"第 22/33 名"就是这么来的。

用**干净的池子**（12 个对手 + 少数几个真实候选,每方法一项）重做,并对对手池
做 400 次随机子抽样（保留 50%–100% 成员）,每次从头重算排名
（`research/round2/field_robustness.py`）。**每个设置赢下这 400 次的比例：**

| 数据集 | `p=0.25` | `p=1.0` | `p=4.0`（出厂） |
|---|---|---|---|
| sp500 | 20.5% | 0.0% | **79.5%** |
| ftse100 | 2.5% | 0.0% | **97.5%** |
| factors | 0.0% | **100.0%** | 0.0% |

**三个设置各自在一个数据集上完胜,在另一个上完败。** "哪个惩罚系数最好"完全由数据集决定,
不存在稳定选择。上表那些 Δ 值因此不应作为"换个设置能加多少分"来读。

同一方法测"要不要换方法"（候选 = 我们 + NCO / SchurComplementary / MinVariance(Denoise) 等）：

| 数据集 | 胜率最高的候选 |
|---|---|
| sp500 | `MinVariance(Denoise)` 76.2%（我们 0%） |
| ftse100 | `NCO` 100%（我们 0%） |
| factors | `MaxDiversification` 61.0% / `MinVariance(Denoise)` 39.0%（我们 0%） |

**在我们这套模拟里,我们从来不是第一名,而且赢家的身份逐数据集漂移。**
这正是"沿前沿滑动、靠噪声挑参数"的另一个例子,Margin 只有 0.03–0.06。

⚠️ 另外注意:**赢我们的那三个方法里,`MinVariance(Denoise)` 与 `MinVariance(Shrunk)`
正是本文 §5 与 Round 2 主报告已经否掉的辩解**——"我用了收缩/去噪协方差,所以我不是
SCM-GMVP"。那条辩解在 5 资产面板上被实测推翻（`p=0` 与 SCM-GMVP 相关性 0.999）。
所以"换个更能得分的方法"这个方向,至少有一条路是**用我们自己已经驳倒的理由去换分**,
不能走。

### 4.6 还试过一条:加"下行风险项"能不能在不牺牲收益的前提下压低回撤

动机：`max_drawdown` 占 15%,而"降低惩罚系数换回撤"要牺牲年化。如果能在**不动惩罚系数**的

（`C + λ·S`,`S` 是同一时间加权下的下行半协方差),锚也按混合矩阵重算——
目标仍是凸二次,求解器**一行没改**（`research/round2/scan_downside_r2.py`）。

| 1.00 | 17.602% / 63.913% | 13.439% / 54.962% | 11.111% / 39.841% |
| 2.00 | 17.832% / 64.084% | — | 11.408% / 39.830% |
| 4.00 | 17.908% / 65.160% | — | 11.308% / 39.821% |

- **sp500：年化与回撤同时上升**——它让组合更激进,不是更防守。ftse100 同样两头上行。
- **只有 5 资产的 factors 上**是轻微双改善（年化 +0.48pp、回撤 −0.04pp）。
- 失败折：**全部 0**。

**这又是一次"被单数据集的小样本骗到"**：5 资产上那 0.19pp 在宽横截面上不成立，
而且方向翻了过来。结论：这是前沿上的移动,不是改进。

### 4.7 关于"怎么让结果更好"的总结

试过的四条路,没有一条能稳定提升：

| 路子 | 结果 |
|---|---|
| 开做空 | 出厂惩罚下得分影响 ≤ +0.0037,却把 Gross 抬到 1.156 → 收益近似为零、风险实在 |
| 调惩罚系数 | 逐数据集反转（赢率 79.5% / 97.5% / 0% 与 0% / 0% / 100%）→ 挑噪声 |
| 换方法/换锚 | 赢家逐数据集漂移（Denoise / NCO / MaxDiversification),Margin 0.03–0.06,且部分赢家踩我们自己驳倒的辩解 → 不可靠 |
| 加下行风险项 | 年化与回撤同时上升,是前沿移动不是改进 → 无效 |

**所以"更好的结果"目前不存在可复现的抓手。** 而出厂设置的真正优势不在得分:
它是**唯一一个合规性由测量确立**的选项（三条禁令逐折零命中、距离已记录),
并且在 `leverage=1` 的四种解读下都合法。**用 0.03–0.06 的噪声换掉一个已被证明不会失败的东西,
是坏的期望值交换。**


对每个设置都在**同一训练窗口**上重建三个被禁组合（EWP / IVP / long-only SCM-GMVP），
逐折算 L1 距离。

- **对 EWP、IVP 的距离：做空让它变大**（sp500：L1_IVP 0.981 → 1.196）。
  原因是 `sum(w)=1` 且带负权重时，权重向量不可能像 `1/σ` 那样全正，
  所以开空头在几何上就远离了 IVP。方向上没有风险。
- **对 SCM-GMVP 的距离：在出厂惩罚下做空让它微增**（sp500：0.738 → 0.755），方向安全；
  而**在不开做空时降低惩罚系数，距离迅速缩小**（sp500：`p=4` 0.738 → `p=1` 0.631
  → `p=0.25` 0.453 → `p=0` 0.217；ftse100：`p=4` 1.048 → `p=0` **0.257**）。
  这才是真正的风险面，也是 §1 第 3 条的依据。
- **精确命中被禁组合的次数：0**（`reports/round2_backtest.json`）。

⚠️ **这个度量尺有它自己的适用边界，必须一起说明。**
被禁的是**long-only** 的 SCM-GMVP，而开做空后可行集本身就变了——
实测 ftse100 上 `p=0, cap=0` 的距离是 0.257，加上 `cap=0.01` 后变成 0.871，
看起来"更远"了。但那个 0.871 是"离 long-only GMVP 更远"，
**并不等于"离 long-short 的最小方差组合更远"**。所以：

- 这个 L1 距离能证明的是**"没有复现被禁的那个 long-only 组合"**；
- 它**不能**证明"目标函数没有变得更偏向最小方差"。那件事的证据在别处：
  `p=0` 在 5 资产上复现被禁组合到相关性 0.999，说明**这个目标函数在低维下
  本来就靠锚正则项（而不是协方差估计器）才避开禁令**，打开做空等于放松了那个项。
- 因此本文不主张"做空已被证明安全"，只主张**"做空没有带来任何可测的收益，
  却引入了一个已测出的 Gross 越界"**。

## 5. 合规检查：做空有没有把组合推向被禁组合？

对每个设置都在**同一训练窗口**上重建三个被禁组合（EWP / IVP / long-only SCM-GMVP），
逐折算 L1 距离。

`short_cap` 是**每资产**的做空上限，**不是**组合层面的做空比例。
同样的 `cap = 0.01`：

| 数据集 | 资产数 | 实际总做空 | Gross |
|---|---|---|---|
| sp500 | 20 | 0.057 | 1.115 |
| ftse100 | 64 | 0.176 | 1.353 |

资产越多，每资产 1% 的额度能累积出的总空头越大。所以本次把
**`short_cap` 当输入量、把"实际总做空"和"Gross"当报告量**，
上文表格里两者都给了。

如果要一个"与宇宙大小无关"的做空比例，需要的是总量预算
`sum(max(−w, 0)) ≤ s`，其可行集是 `{sum(w) = 1, ‖w‖₁ ≤ 1 + 2s}`——
**超平面 ∩ L1 球，没有闭式投影**，需要引入内层一维搜索或 Dykstra 迭代。
考虑到 §4.2 的结论（这一项最多值 0.007 分），没有为它引入迭代投影；
这是一个**被明确记录的功能边界**，不是遗漏。

## 7. 顺带修掉的两个真实缺陷

在做这项工作时发现并修掉了两个既有缺陷，都写进了回归门。

### 7.1 有不合格列时，已收敛的最优解被静默丢弃

`_prohibited_proximity()` 在**不合格子空间**（k 维）上算 IVP，
却拿它去减**全资产空间**（n 维）的权重。只要有一列不合格（历史不足/停牌）：

```
ValueError: operands could not be broadcast together with shapes (6,) (5,)
```

这个异常被 `allocate()` 的外层 `except` 捕获，于是**把已经收敛的 QP 解丢掉，
静默退回 HRP 锚**。症状是 `status` 变成 `fallback_hrp`，而 `main_solver_converged`
其实还是 `True`。

修法：把两个空间显式分开（`weights` 在协方差自己的坐标上，`full` 是全资产空间的写法）。
效果（23 例合成退化面板）：`regularized_qp` **15 → 17**，`fallback_hrp` **2 → 0**。

这个问题在正常数据上不出现（列都合格时 k = n），所以**只有边缘面板才会踩到**——
但它属于"提交的方法其实没在跑"，必须修。

### 7.2 排名百分位把 1e-16 当成不同名次

两个经济上**完全相同**的设置（`cap=0.00` 与 `cap=0.20`，后者根本没 binding、
给出同一个 long-only 组合），因为求解器末次迭代差几个 ulp，
`rankdata` 把它们排成 r=1.000 与 r=0.000——**凭空造出 0.30 的分差**。

修法：排名前按相对容差量化（`np.round(v / (scale·1e-6))`），容差内视为并列。
1e-6 相对量级远低于任何有经济含义的收益/回撤差异，又远高于浮点噪声。

## 9. 边界声明（不含糊）

1. **做空的语义取决于评测框架对 `leverage=1` 的定义，而该定义未被公布。**
   本文给出四种读法与各自后果，并选择在四种读法下都合法的 long-only 出厂设置。
2. **这不构成"我的组合在此轮评分更高"的声明，而且出厂设置并不是模拟得分的最高者**
   （见 §4.4：`p=1 cap=0.05`、`p=0.25 cap=0.20` 在我们的模拟里分别高 +0.018 ~ +0.070，
   代价是 Gross 1.3 – 2.3 且最优设置逐数据集漂移）。
   本文给出的是：格式合规、未被禁组合在每一个测试折上都不出现、对敌意输入稳健，
   以及**出厂设置是唯一在 `leverage=1` 的四种解读下都合法的选择**。
3. **合成退化面板与随机窗口压测不是市场回测成绩**，两者在文档中始终分开陈述。
4. **`short_cap` 与"做空比例"不是同一个量**，见 §6；该边界是有意保留的。
5. **§7 的两个修复改变了旧核心在边缘面板上的行为**，因此"逐位一致"这一声明
   严格成立于 210/220 个 case；另外 10 个 case 以可证伪的方式被单独断言为"有意修复"。
