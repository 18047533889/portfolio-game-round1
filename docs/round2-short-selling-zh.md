## 1. 结论

**做空已经作为一个真正的参数实现在提交文件里，经过机器精度级的数学验证、
逐位不变的回归证明、以及 4 个惩罚系数 × 8 个做空额度的完整扫描；
但出厂设置是关闭的。**

原因不是"保守"，而是三组测量数字：

1. **满仓的前提下，"可做空"与"`leverage=1`"在数学上互斥。**
   净敞口被满仓钉在 1，于是 `Gross = 1 + 2 × 总做空量`。只要开一点空头，Gross 就超过 1。
2. **在出厂惩罚系数下，做空额度基本不 binding，收益与回撤的变动都在可忽略量级**，
   而 Gross 被抬到 1.156。在排名百分位模拟里这些设置的总分是 0.509–0.516，
   而**任意一折失败直接扣 0.51**——用 0.51 的风险去博 0.007 的分差，不划算。
3. **回撤的大幅改善（sp500 上 57% → 31%）只有把 `anchor_penalty` 压到 0 才拿得到**，
   而 0 是在上一轮就已经因"复现被禁的 SCM-GMVP"（5 资产上相关性 0.999）被排除的设置。
   目标函数是"方差 + 锚正则"，没有收益预测项，**多做空只会把组合推向最小方差顶点**。

「做空比例」这个旋钮我手调了 8 档、在 4 个惩罚系数下各扫一遍，全部结果在下文表格与
`reports/round2_short_sweep.{json,txt}`。**老师的规则允许做空，但并不要求做空**；
`allow_short=False` 在 `leverage=1` 的**每一种**解读下都合法。

## 2. 为什么这是一个真冲突，而不是理解问题

skfolio 库里**没有** `leverage` 参数（库内只有财务杠杆类**因子**），
所以 `leverage` 是评测框架自己的规则。它唯一可测量的对应物是
`MultiPeriodPortfolio.long_short_exposure` 的四个量：
`Long` = 正权重和、`Short` = 负权重和、`Net` = 权重和、`Gross` = 绝对权重和。

满仓（`sum(w) = 1`）时恒有

```
Net   = Long − Short = 1
Gross = Long + Short = 1 + 2 × Short
```

于是"`leverage=1`"的四种自然读法与做空的关系是：

| 读法 | 约束 | 做空空间 |
|---|---|---|
| ① Gross 上限 + 强制满仓 | `Gross ≤ 1` 且 `Net = 1` | **无**（数学上只剩 `w ≥ 0`） |
| ② 真杠杆率 | `Gross / Net = 1` | **无** |
| ③ Gross 上限，不强制满仓 | `Gross ≤ 1` | 有，但净敞口 `= 1 − 2×Short` 被压低 |
| ④ 只约束净敞口 | `\|Net\| ≤ 1` | 有，且可保持满仓 |

**long-only 满仓在 ①②③④ 下全部合法。**
而本次实现的 `{w ≥ −c, sum(w) = 1}` 是"满仓 + 每资产可做空"，
它只在 ④ 下合法；在 ① ② ③ 下 Gross 都会越界。

这是一个**不对称赌注**：开启做空只会增加"被判违规"的面数，而失败率占 70% 的分。
所以默认值是关闭，并且这个取舍写在 `configs/submission_round2.json` 的
`short_selling_note` 里，不是藏在代码里。

## 3. 实现了什么

### 3.1 参数

```python
def allocate(returns, *, half_life=63.0, recent_mix=0.25, anchor_penalty=4.0,
             method="regularized", allow_short=False, short_cap=0.0):
```

- `allow_short=False` → 可行集仍是 long-only 单纯形 `{w ≥ 0, sum(w) = 1}`。
- `allow_short=True, short_cap=c` → 可行集换成盒子单纯形 `{w ≥ −c, sum(w) = 1}`。
- `short_cap > 0` 但 `allow_short=False` 会**抛错**，而不是被静默忽略。
- `short_cap` 被限制在 `[0, 0.5]`。

### 3.2 数学：两处闭式都改了，并且都验证过

换成盒子单纯形以后，`project_simplex` 和"单纯形对偶间隙"都不能直接用，
否则求解器的收敛证书会**失效但看不出来**。两处都换成闭式解：

```python
# 投影：平移后就是标准单纯形，用排序阈值法，闭式
u = w + c                          # 双射到 {u ≥ 0, sum(u) = 1 + n·c}
budget = 1.0 + n * c
# ... 排序阈值投影 ...
w = max(z − θ, 0) − c

# 对偶间隙下界：凸集上线性型在顶点取到最小值，仍然闭式
min_g = min(gradient)
lower = (1.0 + n·c) · min_g − c · Σgradient     # c = 0 时退化为 min_g
```

**验证方式不是"权重合法就算过"**，见 `tools/round2_short_projection_check.py`：

| 断言 | 独立参照 | 实测最大误差 |
|---|---|---|
| 投影 = 精确欧氏投影 | 对 KKT 乘子二分求解 | **1.4e-15**（机器精度） |
| 投影 = 精确欧氏投影 | cvxpy 直接解投影问题 | 1.6e-11（求解器容差） |
| 间隙下界 = 线性型最小值 | cvxpy 解 LP | 4.3e-12（求解器容差） |
| 下界确实是下界 | 逐可行点逐个检验 | 无违例 |

### 3.3 证明"加了参数没动老路径"

新增参数最容易出的事故是**顺手改了老代码路径**。这里用冻结的改造前核心做黄金参照
（`research/round2/frozen/core_r2_long_only_80bbd559.py`，SHA256 `80bbd559...`），
对新旧两版跑同一批面板 × 同一组参数，**要求 `np.array_equal` 而不是 `allclose`**：

```
tools/round2_long_only_equivalence.py
  cases compared   : 220
  differences      : 0
  intended fixes   : 10
  LONG-ONLY EQUIVALENCE: IDENTICAL
```

**220 个 case 逐位一致。** 其中 10 个 case 被单独归类为"有意修复"（见 §7），
门会强制要求它们**只以那一种方式**不同：必须走上已认证的 QP 路径、不得留下内部异常、
权重必须合法；`method="hrp"` 的那一例权重还必须逐位不变（只有状态标签被纠正）。

## 4. 手调做空比例：扫描结果

`tools/round2_short_sweep.py`，老师口径回测（`WalkForward(252,20)`、`weight_drift=TRUE`），
4 个惩罚系数 × 8 个每资产做空上限。

### 4.1 sp500（20 资产，403 折，0 失败）

**出厂惩罚系数 `anchor_penalty = 4.0`：**

| `short_cap` | 年化 | 最大回撤 | 实际总做空 | Gross | 与 SCM-GMVP 的 L1 | 模拟得分 |
|---|---|---|---|---|---|---|
| **0.00（出厂）** | **16.407%** | 57.001% | 0.000 | **1.000** | 0.738 | 0.5126 |
| 0.01 | 16.393% | 56.564% | 0.057 | 1.115 | 0.750 | 0.5163 |
| 0.02 | 16.383% | 56.568% | 0.076 | 1.153 | 0.755 | 0.5090 |
| 0.05 | 16.365% | 56.535% | 0.078 | 1.156 | 0.755 | 0.5126 |
| 0.10 – 0.50 | 16.365% | 56.535% | 0.078 | 1.156 | 0.755 | 0.5126 |

- 年化变化 **−0.04pp**、回撤变化 **−0.47pp**：两者都可忽略。
- Gross 从 **1.000 抬到 1.156**：这是唯一实质性的变化，方向是变糟。
- 得分带 0.509–0.516；**任一折失败 = −0.51**。
- `cap ≥ 0.05` 之后完全不变，说明约束已经不再 binding。

**把惩罚系数也一起放开，才看得到做空"有效"的地方：**

| 设置 | 年化 | 最大回撤 | 实际总做空 | Gross | 与 SCM-GMVP 的 L1 | 模拟得分 |
|---|---|---|---|---|---|---|
| `p=4.0, cap=0.00`（出厂） | 16.407% | 57.001% | 0.000 | 1.000 | **0.738** | 0.5126 |
| `p=1.0, cap=0.05` | 15.083% | 50.103% | 0.149 | 1.297 | 0.654 | 0.5309 |
| `p=0.25, cap=0.10` | 13.894% | 39.802% | 0.299 | 1.599 | 0.532 | 0.5309 |
| `p=0.0, cap=0.10` | 13.207% | **35.513%** | 0.556 | 2.113 | 0.396 | — |
| `p=0.0, cap=0.00` | 13.432% | 41.513% | 0.000 | 1.000 | **0.217** | 0.4834 |

规律非常清楚：**降低惩罚系数换来回撤改善，代价是年化下降，同时 Gross 一路抬升、
与 SCM-GMVP 的距离一路缩小。** `p=0` 那一行的 L1 = 0.217（出厂是 0.738），
而这正是上一轮已经判定为"复现被禁组合"的设置。

### 4.2 排名百分位模拟：70% 那一项根本不区分

在模拟对手场（12 个 skfolio 优化器）里，所有 **0 失败**的候选——包括我们的每一个设置
和 10 个对手方法——`r_fail` 是**同一个常数 0.523**（并列共享秩）。
只有 HRP/HERC（99.8% 失败率）拿到 0.012。

也就是说，占 70% 的分项**不区分任何东西**；真正的分差只来自另外 30%，上限 0.30。
我们全部设置的总分落在一个约 **0.075 宽**的带里，而**任一折失败 = −0.51**。

**这就是整个取舍的量化形式：换个做空比例值 ±0.007，弄坏一折值 −0.51。**

## 5. 合规检查：做空有没有把组合推向被禁组合？

对每个设置都在**同一训练窗口**上重建三个被禁组合（EWP / IVP / long-only SCM-GMVP），
逐折算 L1 距离。

- **对 EWP、IVP 的距离：做空让它变大**（sp500：L1_IVP 0.981 → 1.196）。
  原因是 `sum(w)=1` 且带负权重时，权重向量不可能像 `1/σ` 那样全正，
  所以开空头在几何上就远离了 IVP。方向上没有风险。
- **对 SCM-GMVP 的距离：在出厂惩罚下做空让它微增**（0.738 → 0.755），方向安全；
  但**一旦降低惩罚系数，距离迅速缩小**（`p=1` 时 0.631、`p=0.25` 时 0.453、
  `p=0` 时 0.217）。这才是真正的风险面，也是 §1 第 3 条的依据。
- **精确命中被禁组合的次数：0**（`reports/round2_backtest.json`）。

## 6. 一个必须说清的限制：每资产上限 ≠ 做空比例

`short_cap` 是**每资产**的做空上限，**不是**组合层面的做空比例。
同样的 `cap = 0.01`：

| 数据集 | 资产数 | 实际总做空 | Gross |
|---|---|---|---|
| sp500 | 20 | 0.057 | 1.115 |
| ftse100 | 64 | 0.176 | 1.353 |

资产越多，每资产 1% 的额度能累积出的总空头越大。所以本次把
**`short_cap` 当输入量、把"实际总做空"和"Gross"当报告量**，
上文表格里两者都给了。

如果要一个"与宇宙大小无关"的做空比例，需要的是总量预算
`sum(max(−w, 0)) ≤ s`，其可行集是 `{sum(w) = 1, ‖w‖₁ ≤ 1 + 2s}`——
**超平面 ∩ L1 球，没有闭式投影**，需要引入内层一维搜索或 Dykstra 迭代。
考虑到 §4.2 的结论（这一项最多值 0.007 分），没有为它引入迭代投影；
这是一个**被明确记录的功能边界**，不是遗漏。

## 7. 顺带修掉的两个真实缺陷

在做这项工作时发现并修掉了两个既有缺陷，都写进了回归门。

### 7.1 有不合格列时，已收敛的最优解被静默丢弃

`_prohibited_proximity()` 在**不合格子空间**（k 维）上算 IVP，
却拿它去减**全资产空间**（n 维）的权重。只要有一列不合格（历史不足/停牌）：

```
ValueError: operands could not be broadcast together with shapes (6,) (5,)
```

这个异常被 `allocate()` 的外层 `except` 捕获，于是**把已经收敛的 QP 解丢掉，
静默退回 HRP 锚**。症状是 `status` 变成 `fallback_hrp`，而 `main_solver_converged`
其实还是 `True`。

修法：把两个空间显式分开（`weights` 在协方差自己的坐标上，`full` 是全资产空间的写法）。
效果（23 例合成退化面板）：`regularized_qp` **15 → 17**，`fallback_hrp` **2 → 0**。

这个问题在正常数据上不出现（列都合格时 k = n），所以**只有边缘面板才会踩到**——
但它属于"提交的方法其实没在跑"，必须修。

### 7.2 排名百分位把 1e-16 当成不同名次

两个经济上**完全相同**的设置（`cap=0.00` 与 `cap=0.20`，后者根本没 binding、
给出同一个 long-only 组合），因为求解器末次迭代差几个 ulp，
`rankdata` 把它们排成 r=1.000 与 r=0.000——**凭空造出 0.30 的分差**。

修法：排名前按相对容差量化（`np.round(v / (scale·1e-6))`），容差内视为并列。
1e-6 相对量级远低于任何有经济含义的收益/回撤差异，又远高于浮点噪声。

## 9. 边界声明（不含糊）

1. **做空的语义取决于评测框架对 `leverage=1` 的定义，而该定义未被公布。**
   本文给出四种读法与各自后果，并选择在四种读法下都合法的 long-only 出厂设置。
2. **这不构成"我的组合在此轮评分更高"的声明。** 本文给出的是：
   格式合规、未被禁组合在每一个测试折上都不出现、以及对敌意输入稳健。
3. **合成退化面板与随机窗口压测不是市场回测成绩**，两者在文档中始终分开陈述。
4. **`short_cap` 与"做空比例"不是同一个量**，见 §6；该边界是有意保留的。
5. **§7 的两个修复改变了旧核心在边缘面板上的行为**，因此"逐位一致"这一声明
   严格成立于 210/220 个 case；另外 10 个 case 以可证伪的方式被单独断言为"有意修复"。
